GET STARTED

Run a sorting example

  1. Choose an input. Enter a sequence containing S and P, or select a built-in example. Spaces are ignored.
  2. Load it. Press Load to place the sequence between the tape boundary markers and reset the machine.
  3. Watch one transition. Press Step (or Space) to read, write, move, and change state once.
  4. Run automatically. Press Run; adjust the speed slider to change the delay. Pause stops the animation.
  5. Inspect the result. Accepted means a clean scan found the tape sorted. The trace lists each rule that ran.

PARCEL CLASSIFICATION

Try the simulated scanner

  1. Enter a sample ID. Use PKG-1001 for Priority Express or PKG-1002 for Standard Delivery.
  2. Scan the ID. The offline demo looks up a local sample shipping record; it does not access a camera, barcode reader, network, or real shipping database.
  3. Add and load. Add successfully classified parcels to a batch, then load it into the Turing machine. Priority maps to P; Standard maps to S.
  4. Sort and route. Run the machine. Once it accepts, the result is grouped into priority and standard destination lanes.

Try UNREADABLE or NO-RECORD to see the exception path. These cases are held for manual review; the demo never guesses a parcel class.

PRESENTATION WALKTHROUGH

Five steps for a classroom demo

  1. Start the guided demo and explain that parcel detection is simulated.
  2. Show PKG-1002 being matched to a Standard shipping record and added as S.
  3. Show PKG-1001 being matched to a Priority record and added as P; the tape input becomes SP.
  4. Run the Turing machine and point out the head, transition trace, and swap from SP to PS.
  5. Finish with the separate priority and standard destination lanes. Explain that real hardware integration needs scanners, tracking, industrial controls, and safety engineering.

SAMPLE TEST CASES

Expected behavior

  • PKG-1001: ID found → Priority Express → P.
  • PKG-1002: ID found → Standard Delivery → S.
  • UNREADABLE: ID cannot be read → manual review; do not classify.
  • NO-RECORD: ID is readable but missing from sample records → manual review; do not classify.
  • SP: sorter output PS → one priority parcel in the priority lane and one standard parcel in the standard lane.
  • PPSS: already sorted → output remains PPSS with zero adjacent swaps.

SYMBOL KEY

What appears on the tape

  • S — standard parcel
  • P — priority parcel
  • □ — blank tape cell
  • ⊢ — left boundary marker
  • ⊣ — right boundary marker

The head marker points at the cell that will be read on the next step. State and transition panels update after every machine operation.

CONVEYOR VIEW

Follow the parcels

The animated conveyor below the tape mirrors each parcel symbol using local parcel illustrations. Priority and standard parcels have different shipping labels. The scanner follows the current Turing machine head, and the parcel image changes during the two writes that make an adjacent swap. Use the conveyor alongside the tape to connect the real-world analogy to each formal machine step.

The scanner above is also simulated and uses sample IDs stored in the project. This simulator updates a symbolic tape; the sorting concept could be used in an industrial system with parcel identification, suitable conveyor controls, and safety engineering.

CONTROLS

Buttons & keyboard

  • Step — execute one transition.
  • Run — execute transitions automatically.
  • Pause — stop automatic execution.
  • Reset — restart the currently loaded input.
  • Space — execute one step when focus is not in a form control.

UNDERSTANDING THE RESULT

Accepted or rejected?

The machine accepts when a complete left-to-right pass finds no S P pair. That means every priority parcel is before every standard parcel.

Only S/P inputs are valid. A missing transition or safety step-limit halts as rejected; the status area explains why.
